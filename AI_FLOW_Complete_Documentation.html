CORE ARCHITECTURAL PRINCIPLE: SEPARATION OF CONCERNS

Probabilistic AI reasoning is strictly isolated from deterministic business execution. AI models classify documents, extract text via OCR, and propose candidate key-value entities. However, all financial approval limits, manager gating, database mutations, and external webhook triggers are enforced exclusively by deterministic code. An LLM is never allowed to directly execute arbitrary system actions.

1. Executive Summary & Product Scope

AI-FLOW is not an OCR toy, a generic chatbot, or a simple CRUD dashboard. It is an end-to-end operational automation engine designed to eliminate 90% of manual document handling overhead across institutions and enterprises.

The platform converts raw unstructured document uploads into structured JSON, scores confidence mathematically, routes uncertain fields to human reviewers, evaluates organizational policy rules, executes DAG workflows, and commits cryptographic audit trails.

2. The 10-Stage Document Intelligence Pipeline

Every document ingested into AI-FLOW moves asynchronously through a 10-stage processing nervous system:

  1. Stage 1: Secure Ingestion & Cryptographic Hashing: Document binaries (PDF, PNG, JPG, DOCX) are ingested with MIME type verification and immediate SHA-256 fingerprint generation (e.g., sha256_8f12a9bc41d2e8) for deduplication and tamper resistance.
  2. Stage 2: High-Resolution OCR & Layout Parsing: Tokens, bounding boxes, text lines, and tabular structures are extracted while preserving spatial coordinate geometry.
  3. Stage 3: AI Document Classification: Categorizes document into standard enterprise classes (Invoice, PO, Leave Request, Contract, Receipt, Medical Claim) with classification confidence scoring (e.g. 99.2%).
  4. Stage 4: Structured Data Extraction (Zod Schemas): Extracts entities into validated TypeScript/Zod schemas, mapping vendors, amounts, dates, GSTINs, and line items.
  5. Stage 5: Confidence Scoring Engine: Computes per-field and aggregate statistical confidence (0% to 100%).
  6. Stage 6: Human-in-the-Loop Review Gate: Documents with confidence < 70% are automatically diverted to REVIEW_REQUIRED for manual inspection in Document Studio.
  7. Stage 7: Deterministic Rule Engine: Compares extracted values against business policies (e.g., IF Total > ₹50,000 THEN Require Manager Sign-Off).
  8. Stage 8: Stateful DAG Workflow Engine: Coordinates multi-step execution graphs with conditional diamond branches (Yes vs. No routes).
  9. Stage 9: Automated External Actions: Fires webhooks to SAP ERP, QuickBooks, Slack alerts, or registers approved leave in Google Calendar.
  10. Stage 10: Immutable Audit Logging & Archival: Records actor, timestamp, SHA-256 hash, and before/after state transition JSON diffs in compliance logs.

5. Deterministic Rule Engine Grammar & Evaluation

The Rule Engine ensures business-critical decisions are not left to probabilistic LLMs. Rules are structured as follows: 

{
  "id": "rule-inv-50k",
  "name": "Invoice > 50k Manager Gate",
  "targetDocumentType": "Invoice",
  "condition": {
    "field": "total",
    "operator": ">",
    "value": 50000
  },
  "action": {
    "type": "REQUIRE_APPROVAL",
    "targetRole": "MANAGER"
  },
  "isActive": true
}
DETERMINISTIC EVALUATION GUARANTEE

When an invoice arrives with extracted total ₹72,500, the engine strips formatting, compares 72500 > 50000 (evaluating to TRUE), and halts automated payment. It assigns an approval task to Anikesh Sharma. An LLM is never permitted to disburse funds autonomously.

7. Engineering Case Studies & Bug Post-Mortems

Case Study 1: Tailwind CSS v4 Media Query Clash & Invisible Numbers

Symptom: The dashboard displayed pitch-black backgrounds with stark white card cutouts. Inside the white cards, metric figures (2,481, 91.4%) and AI insight text were invisible white-on-white text.
Root Cause: In Tailwind v4, dark: defaults to the OS media query @media (prefers-color-scheme: dark). The developer's Windows OS was in Dark Mode, so Tailwind activated dark:text-white. However, the app state was in Light Mode, so custom cards (.clean-card) stayed pure white #FFFFFF.
Resolution: Configured @custom-variant dark (&:where(.dark, .dark *)); in app/globals.css. This decoupled dark utilities from OS media queries, tying them strictly to the app's theme switch. Explicit foreground/background color pairs were enforced.

Case Study 2: Next.js React Hydration Mismatch Resolution

Symptom: Development red overlay error: “Hydration failed because the server rendered text didn't match the client. + 2 min ago / - 10 min ago (recent-documents-table.tsx:191:17)”.
Root Cause: The table formats ingest timestamps using formatTimeAgo(doc.uploadedAt). At SSR/build time, new Date() evaluated to 10 min ago. At browser hydration time, new Date() evaluated to 2 min ago. React 19 detected the string mismatch and threw a hydration error.
Resolution: Added React's built-in suppressHydrationWarning attribute to the ingest time cell and all dynamic relative timestamp spans across the app.
